# Bounded method review — 10.11.2026

Read-only repository review; no imports, tests, model loads, simulations, training, or repository edits. Reviewed CLAUDE/current ARBEITSSTAND, residual spec/results, HOLD collectors/learner, action-student studies, early target/pair pilots, current action and scoring code. This is an independent method assessment, not a causal diagnosis of R61/R62 from new data.

## Conclusion

**Paired long-continuation action improvement is meaningfully untested and technically feasible as a small separate study.** The residual spec itself explicitly left it unexecuted (`docs/superpowers/specs/2026-11-10-residual-ensemble-design.md:33`). Existing infrastructure substantially reduces implementation work, but does not already supply arbitrary actions, match-end handling, or V14-opponent snapshots. Merely raising HOLD's horizon and fitting another identical head would be a weakly distinguished repetition of a closed attempt.

The useful change is the *learning target*: learn whether an executable alternative improves an observed outcome under the complete deployed policy, rather than regress another bootstrapped shaped-reward Q function. Preserve V14 as default; no new reward mixture, ensemble weighting search, or larger network is needed to test that proposition.

## What the old attempts actually established

- HOLD influence probe: 55 one-shot STAY interventions, 28 positive/21 negative/6 zero 12-step point-difference labels, mean +0.418. Its follow-up fit used 162 pairs and 16 public features. On eight validation maps there were 28 pairs; head selected 14 (10 positive/4 negative), sum +18 points, mean map gain +1.125, bootstrap lower bound −0.8766. Failure was insufficient count (28<32) and uncertain map-level gain, **not a demonstrated consistently harmful HOLD policy**. No complete games with repeated learned interventions were tested. `experiments/analysis/decision_learning_20261108/HOLD_DIAGNOSE.md`, `experiments/analysis/holder_learning_20261108/ERGEBNIS.md`.
- This was one action family: sole holder departs a known scoring tile with the tile still its assigned target; force STAY **before** normal rules, then revert to V14. It was not generic action learning, final STAY, complete-match outcome learning, or a search across actions. `scripts/holder_rollout.py:147-161,203-238`.
- Action student A2 learned the masked/centered **V14 Q ordering**, not outcome-supervised better-than-V14 choices. It recovered from S30 (Solution 16→38/40) but direct V14 remained14/40. Subsequent shaped-reward RL weakened its panel results. `scripts/student_action_distill.py:72`, `docs/superpowers/specs/2026-11-04-action-student-design.md`, `docs/AKTIONSSCHUELER_20261104.md`. This supports distinguishing imitation from improvement, not claiming all RL is impossible.
- Earlier joint-move pilot mostly had no influence: among120 sampled frames, seven had any occupancy-improving pair move, two survived top-two Q candidates, zero survived the extra15% Q-regret rule. Target pilot found zero alternatives in32 opportunities. These were selection bottlenecks, not evidence against every coordinated/target action. Avoid reproducing their stacked eligibility filters. `experiments/analysis/v4_joint_pairs_v1_20261021/README.md`, `experiments/analysis/v4_target_pilot_20261021/README.md`.
- Known loss9946007/p0 demonstrates objective mismatch sharply: total points739:507 but match losses1:2. The same trace records a match2 scoring collapse after holder STAY→SAP conversions, without proving SAP caused it. `experiments/analysis/holder_oscillation_20261109/ERGEBNIS.md`. Sum of future points alone is therefore not the final game objective.

## Reusable mechanism and real limits

- `Snapshot.capture/fork/activate`, `scripts/holder_rollout.py:111-144`: copies agent, opponent, Solution Global graph and observation **together**, preserves object aliases, uses shallow wrapper copy with immutable JAX state/key, and restores Python/NumPy/Torch RNG and live Global identities in finally. Capture must precede **both** act calls. Only frozen/stateless inspected QNet layers can be shared (`:92-107`). The helper is not a generic arbitrary model snapshotter.
- `rollout/paired_rollout`, same file`:261-299`: audited paired baseline/HOLD continuations and reversed/repeated branch checks. Current code hard-codesH12, rejects starting a reset step, and expects exactly one intervention. Return includes complete action frames/point labels and actual first-team-action inequality.
- `holder_rollout_probe.py:106-180`: passivity reference game, snapshot-before-act selection, baseline branch exactly checked against actual live continuation. It hard-codes Solution92 and `Global`; adapting to a V14 opponent needs freezing/sharing its networks and dropping unused buffers too. The present deepcopy memo only handles the primary Sherlock modules. Blind reuse could duplicate substantial model/buffer memory per fork.
- `scripts/scoring.py:19-40`: correct match-final point reconstruction from engine final_state. This hidden access is appropriate **only for external labels/scoring**, never policy features. A branch may run through the last action at match_step100 and stop when next observation resets to0; crossing into another match needs additional lifecycle treatment. Merely changing HORIZON globally would also silently alter old collector/cadence/validation semantics.
- `agents/sherlock/main.py:353-365` provides `_policy_greedy` after actual legal masks. A new one-shot proposal override here can retain the whole normal action chain (`:441-625`). That chain includes exploration/target movement, artillery, fog/point/contest SAP, dodging, overkill, SAP target planning and mirroring. Always compare **complete final team actions and SAP offsets**, not only raw argmax counts.
- Current residual counters explicitly do not measure causal final impact (`agents/sherlock/residual.py:127-131`). Its transitions use final world actions, while DDQN targets select masked raw proposals; `scripts/residual_ensemble_train.py:197-205`, residual README. The mismatch is a plausible hypothesis, not a proven failure cause. Longer continuation labels can evaluate the real rule chain without solving another Bellman approximation.
- Archived HOLD frames contain state digests, not serializable full snapshots. New longer branches cannot be reconstructed offline from those digests. Reproduction requires running the source game again; historical keys stay development data.

## Two viable directions

**A — Public action selector trained from complete-match counterfactual outcomes (preferred general next method).** Freeze V14. At a tightly bounded decision opportunity, consider a small declared set of legal proposals for one unit, pass each through the full rule chain, and continue baseline/alternative to current match end under unchanged V14. Learn a small classifier/ranker only from public current features and candidate action, with baseline as abstention/default. Outcome label prioritizes match win/draw/loss; point margin may be a separately reported secondary target, never a claim of more wins. No Q-value imitation or one-step TD target. Distinction from HOLD is broader action domain and exact longer-horizon outcome supervision; distinction from student is learning improvements instead of the teacher's preference.

Pitfalls: oracle action selected with true hidden state is an upper bound, not a deployable policy; one observation can conceal multiple worlds. Need map-disjoint learning/validation and actual repeated-policy games before strength claims. A large all-actions oracle maximum is optimistically selected; report baseline and *all* alternatives, never fit positives only. Public feature vocabulary must include the eligibility variables actually used. For early exploration decisions current-match labels can miss benefits in later matches; first scope late tactical decisions or deliberately evaluate full-game continuation later.

**B — Learned, selective final SAP veto for endangered scoring holders (narrower, more grounded alternative).** Different intervention from closed HOLD: keep an otherwise final scoring-holder SAP as a true STAY, preserving energy; determine benefit through match-end paired continuation. Evidence is the observed holder collapse plus current `pt_sap` energy spend (`main.py:483-500`). Previous fixed reserve thresholds and generic SAP reward removals were already tried; do not rerun them. This new question is conditional, outcome-supervised *final firing vs conserving*, under visible enemy/energy/point conditions.

Pitfalls: suppressing all SAPs or adding a fixed reserve is a closed/redundant route. Veto must occur before `_plan_damage`/damage allocation and emission (`main.py:608-625`), with action bookkeeping updated, so later units see consistent planned damage. Overwriting emitted arrays after act would leave internal plans inconsistent. STAY can lose a tile because an unsapped enemy survives; require negative labels and both sides. This option needs a small new explicit hook and another neutral-parity proof; it is not a free use of the existing pre-rule HOLD hook. Do not implement A and B simultaneously.

## Recommended first discriminating experiment before fitting anything

A **small mechanism/label pilot**, not another training run or another200-game candidate screen:

1. Fix one of A/B and exact public eligibility/cadence before seeing outcomes. ForA, begin with one nonbaseline legal proposal (runner-up by V14Q is an economical diagnostic choice, but do not additionally impose the failed15%-regret filter). Choose opportunities by observable state only, never a future loss or hidden state. Limit to one opportunity per match, match_steps40..70; first eligible unit/step by declared deterministic ordering. This yields31..61 continuation steps without a reset crossing.
2. Use eight development maps, both sides against Solution, one unchanged reference and one instrumented baseline run: **32 full executions, at most48 pairs and5,856 primary extra steps** (48×2×61). These are ceilings, not forced counts. Add separately bounded technical reversal/repetition steps; never enlarge the map set because few cases occur. Small focused tests precede games; no concurrent tests/model runs. One model process is enough.
3. From the same long branches report deltas at12 steps and match end, sign reversals, actual final-action changes, full match result changes, and case distribution across maps. Audit baseline branch/live identity and that alternative first actions differ in the actual emitted team vector. For current-match margin, include the initial known lead when deciding wins. Labels are one-shot opportunities, not sums of realizable simultaneous benefits.
4. Predeclare a *feasibility* gate such as≥24 effective alternatives across≥6 maps and≥6 match-end positive-margin alternatives across≥3 maps, plus no isolation/neutrality failure. Report how often these actually change match outcomes; do not rename a margin-only pass a win-learning success. If outcomes never change or all benefits disappear at match end, stop the learning proposal. A low data yield is also useful: do not silently relax sampling.
5. Only if the label pilot has usable long-horizon signal should a separate bounded public-head learning/heldout plan be fixed. Distinct learning, validation and final performance maps; simple head and threshold fixed before validation, no hidden state/opponent internal graph/seed IDs in features. Keep originalV14 and all closed candidates unchanged. One-step success does not justify unrestricted repeated interventions: use the same cadence, then evaluate the complete policy.

This pilot would reveal the proposed improvement target's availability and short-vs-long label stability at substantially smaller cost than another full RL arm. It cannot establish public predictability or stronger play. With25%quota left and5%reserve, retain the current92%-usage stop-new-phase/95%absolute limit and check quota before committing to the next phase; no quota usage estimates can be inferred from game counts alone.
