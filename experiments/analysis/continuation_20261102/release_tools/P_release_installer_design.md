## Three-file transaction, backups and foreign writers

Acquire repository-common heavy-resource lock plus a release-writer flock for
the entire transaction/recovery. Validate fresh receipt ownership UNDER the
lock; no exception may overwrite another invocation's journal. Target root,
HEAD, old hashes, QC/bundle/evidence and no-job checks repeat immediately before
the first filesystem mutation. Never change runtime code or performance03e.

Create a new immutable backup directory inside the transaction root containing
both old `.pth`, old ZIP and canonical manifest (absolute original paths, old
hashes/sizes, bundle hash, target HEAD). Use exclusive file creation, copy+fsync,
hash verification, directory fsync and read-only modes. An existing backup or
transaction directory is refused; no legacy blind-skip/reuse. It remains a
durable rollback record, never deleted after an error.

Prewrite and fsync new and rollback copies on EACH target's filesystem, checking
all hashes. Persist journal `prepared` and per-target intent BEFORE mutation;
fsync journal and its directory. Require all readers/writers stopped: three
regular files cannot be switched as one atomic filesystem operation.

**Avoid the compare-then-`os.replace` foreign-writer race.** Proposed conservative
publish primitive under the exclusive window:

1. Move the current target to this transaction's unique, absent holding name
   in the same directory. Record/recheck its expected inode+hash after the move;
   preserve any unexpected moved bytes instead of overwriting them.
2. Publish the prewritten new file with an atomic no-overwrite hardlink to the
   now-vacant target name, then remove the staging link. If another writer filled
   the target, linking fails; no foreign target is overwritten.
3. Fsync target directory, record new inode+hash and journal `p0_swapped`,
   `p1_swapped`, `zip_swapped`, then final verify all three and `committed`.

This gives individual atomic name publication plus recoverable whole-transaction
semantics, with a brief absent-target interval inside the required reader-free
window. It does not claim simultaneous three-file atomicity. Compared with
`os.replace`, the no-overwrite primitive protects unexpected concurrent target
creation. Noncooperating in-place mutation is detected by inode/hash rechecks;
the exclusive-writer condition remains a real prerequisite, not an assumption
that a flock controls arbitrary third-party processes.

On any ordinary exception or handled HUP/INT/TERM, block further interrupt
signals, reconcile each actual target/holding/staging entry with the durable
journal, and restore all three OLD files using the same no-overwrite primitive.
Only remove/move a target still matching this transaction's recorded installed
inode+new hash. If a foreign file appears, do not overwrite it: preserve holding
bytes/backups, mark `rollback_conflict` and report the exact path. A full rollback
must verify all three old hashes before `rolled_back`. No exception may report
success or silently leave a mixed set as accepted.

SIGKILL/power loss cannot run cleanup. A separate `recover --transaction ...
--authorization ... --recover` command performs ONLY journal-bound rollback
after lock/quiet-window/ownership checks; never resumes installation. Every
transitional intent is durable enough to distinguish absence, owned new state,
old state and foreign conflict. A crash with a pending journal blocks a new
transaction until recovery/manual resolution. Reports preserve failure and all
original evidence. Root should accept the no-overwrite publication approach
before implementation; ordinary unconditional replacement cannot provide the
requested foreign-concurrent-change protection.

## Synthetic verification plan

Use only small temporary byte files, fake staged ZIPs and full synthetic JSON/
CSV evidence. Constants are patched only in tests to hashes of synthetic bytes;
the production CLI has no override flags for the three fixed real identities.
Test-first RED/GREEN for:

- Complete eligible structured bundle accepted; each missing/false numeric gate,
  incomplete counts, rejected audit, unhashed or changed summary/CSV/state/master,
  closure/QC/3.10/config/tensor mismatch rejects without active writes.
- Explicit install/authorization, exact target paths/old hashes, no-job/lock and
  fresh output guards; reject alias/symlink/hardlink targets and stale evidence.
- Success updates both P weights and ZIP and verifies immutable old backup.
- Failure/signals at each target transition restore all old bytes; failure
  records survive; no partial pair counts as committed.
- Foreign concurrent target creation/content replacement is preserved and a
  rollback conflict reported; another invocation's receipt cannot be replaced.
- Crash-intent fixtures recover only original OLD files, never continue install;
  malformed or foreign journals fail closed. Fsync and signal-restoration paths.

No real evidence bundle, staged P ZIP, model import, install, game, course runner,
environment provision, upload or repository commit is part of this preparation.
